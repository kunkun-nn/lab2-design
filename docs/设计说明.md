# 设计说明

## 1. 架构选择

采用**模块化单体**，原因是课程原型由一人开发，微服务会引入部署、事务和联调成本。模块按业务边界划分，模块之间通过接口和领域事件交互，后续可拆分为独立服务。

- 接入层：顾客端、商家工作台、骑手 App、平台管理后台、API 网关、认证与权限。
- 业务模块：商品与店铺、交易（订单/库存/支付/退款）、履约（派单/配送/异常）、治理（用户/统计/审计）。
- 基础设施：MySQL、Redis、消息队列、对象存储、第三方支付沙箱、地图/定位、监控告警。

## 2. 模块职责

| 模块 | 职责 | 主要依赖 |
|---|---|---|
| 商品与店铺 | 店铺资料、营业状态、菜品/规格、库存查询 | MySQL、Redis、对象存储 |
| 交易 | 购物车、下单、价格快照、库存扣减/回补、支付、退款 | 商品模块、MySQL、MQ、支付沙箱 |
| 履约 | 派单、取餐、配送、送达、配送异常 | 交易模块、MQ、地图、MySQL |
| 治理 | 用户/角色、查询统计、审计日志、规则配置 | MySQL、MQ |
| 认证与权限 | 登录、Token、角色和数据范围校验 | 用户/角色 |

## 3. 关键设计

- 订单状态机 + version 乐观锁，禁止直接改状态字段。
- 订单号、请求号、支付流水号唯一；支付回调幂等。
- 下单事务内扣减库存；取消/退款回补库存，且只回补一次。
- 模块间同步调用用于强一致校验（订单→库存），异步领域事件用于通知、派单、统计和审计。
- 关键操作日志只追加，不修改、不删除；日志写入失败时业务事务回滚。

## 4. 数据存储

MySQL 保存用户、地址、店铺、菜品、规格、购物车、订单、明细、地址快照、支付、配送、退款、日志；Redis 保存菜品缓存、幂等键和限流；消息队列传递 OrderPaid、OrderReady、DeliveryFailed、OrderCompleted；对象存储保存菜品图片。

## 5. UI

采用 390×844 移动端和 1440×900 桌面端两种画布；深蓝主色、橙色行动色、18px 圆角、44px 触控高度；顾客端移动优先，商家/管理端桌面优先。
